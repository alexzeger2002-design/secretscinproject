## ⚠️ Потенциальные проблемы

### Критичные (требуют внимания)

1. **Race conditions в `updateBotUrl`**
   - **Проблема:** В `Landing.tsx` функция `updateBotUrl` может вызываться одновременно из:
     - Интервала (каждые 30 сек)
     - Event listener (focus)
     - Первоначального таймаута
   - **Риск:** Множественные одновременные запросы к API, дублирование визитов
   - **Решение:** Добавить флаг `isUpdating` и AbortController для отмены предыдущих запросов

2. **Отсутствие защиты от дублирования визитов**
   - **Проблема:** При быстром переключении вкладок или фокусе может создаваться несколько визитов
   - **Риск:** Неточная аналитика, лишняя нагрузка на БД
   - **Решение:** Debounce для `updateBotUrl` или проверка существующего визита

3. **Нет обработки offline режима**
   - **Проблема:** При потере интернета пользователь не получает обратной связи
   - **Риск:** Плохой UX, пользователь думает что сайт сломан
   - **Решение:** Service Worker для кеширования, индикатор offline статуса

### Средние (рекомендуется исправить)

4. **ErrorBoundary не отправляет ошибки на сервер**
   - **Проблема:** Ошибки React компонентов только логируются в консоль
   - **Риск:** Критические баги остаются незамеченными
   - **Решение:** Интеграция с Sentry/LogRocket или собственный endpoint для логирования

5. **Нет мониторинга производительности**
   - **Проблема:** Нет метрик времени загрузки, ошибок API, производительности
   - **Риск:** Проблемы обнаруживаются только пользователями
   - **Решение:** Vercel Analytics, Web Vitals, или кастомный мониторинг

6. **Интервал обновления может быть избыточным**
   - **Проблема:** Обновление каждые 30 секунд создает постоянную нагрузку
   - **Риск:** Лишние запросы, особенно при множестве открытых вкладок
   - **Решение:** Увеличить интервал до 60-120 сек или использовать WebSocket для push обновлений

7. **Нет кеширования статики**
   - **Проблема:** Видео и изображения загружаются каждый раз
   - **Риск:** Медленная загрузка, лишний трафик
   - **Решение:** Настроить Cache-Control заголовки в Vercel или использовать CDN

### Низкие (можно улучшить)

8. **Нет индикации загрузки при медленном API**
   - **Проблема:** Пользователь не видит что происходит при задержке > 4 сек
   - **Решение:** Skeleton loader или индикатор "Обновление..."

9. **Нет обработки случая полной недоступности API**
   - **Проблема:** Если API полностью недоступен, пользователь видит дефолтную ссылку без объяснений
   - **Решение:** Toast уведомление или индикатор статуса API

10. **Зависимость от внешних сервисов без fallback**
    - **Проблема:** Если Render (бэкенд) недоступен, сайт работает, но без аналитики
    - **Решение:** Локальное кеширование последних данных или очередь запросов

## 🔧 Рекомендации по улучшению

### Приоритет 1 (Критично)

1. **Добавить защиту от race conditions:**
```typescript
// В Landing.tsx
const isUpdatingRef = useRef(false);
const abortControllerRef = useRef<AbortController | null>(null);

const updateBotUrl = async () => {
  if (isUpdatingRef.current) return;
  
  // Отменяем предыдущий запрос
  if (abortControllerRef.current) {
    abortControllerRef.current.abort();
  }
  
  abortControllerRef.current = new AbortController();
  isUpdatingRef.current = true;
  
  try {
    // ... существующий код с signal: abortControllerRef.current.signal
  } finally {
    isUpdatingRef.current = false;
  }
};
```

2. **Добавить debounce для обновлений:**
```typescript
import { debounce } from 'lodash-es';

const debouncedUpdateBotUrl = useMemo(
  () => debounce(updateBotUrl, 2000),
  []
);
```

### Приоритет 2 (Важно)

3. **Интеграция мониторинга ошибок:**
   - Добавить Sentry или LogRocket
   - Настроить алерты на критические ошибки

4. **Улучшить обработку offline:**
   - Service Worker для базового кеширования
   - Индикатор статуса подключения

5. **Оптимизировать интервалы:**
   - Увеличить интервал обновления до 60+ секунд
   - Использовать Page Visibility API для паузы обновлений при неактивной вкладке

### Приоритет 3 (Улучшения)

6. **Добавить метрики производительности:**
   - Web Vitals (LCP, FID, CLS)
   - Время ответа API
   - Процент успешных запросов

7. **Настроить кеширование:**
   - Cache-Control для статики
   - HTTP/2 Server Push для критичных ресурсов
